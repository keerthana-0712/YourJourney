# Stars

A **Star** on GitHub is similar to a bookmark, favorite, or like.

In simple words:

> Stars help you save repositories that you find useful or interesting.

Developers use stars to:

* bookmark repositories
* discover popular projects
* support open-source projects
* keep track of resources

---

# What Does a Star Mean?

When you click the ⭐ Star button on a repository, GitHub saves it to your account.

This helps you easily find the repository later.

Think of it like:

```txt id="m8q2vp"
YouTube → Like

Instagram → Save

GitHub → Star
```

---

# Why Developers Use Stars

Developers star repositories to:

* save useful projects
* remember learning resources
* track interesting tools
* support creators
* discover quality projects

Stars are widely used across GitHub.

# Where Can You See Your Starred Repositories?

GitHub stores them in your profile.

You can view:

```txt id="r8m4vp"
Profile → Stars
```

This acts like your personal collection of useful repositories.

# Why Stars Matter

Stars help identify repositories that many developers find useful.

Generally:

* more stars = more popularity
* more stars = larger community
* more stars = higher visibility

However:

> A repository with fewer stars can still be extremely valuable.

Always evaluate projects based on quality, not only star count.

# Stars vs Forks

Many beginners confuse stars and forks.

| Stars               | Forks                |
| ------------------- | -------------------- |
| Bookmark repository | Create your own copy |
| Save for later      | Contribute or modify |
| No code changes     | Allows changes       |
| Personal collection | Development workflow |

Simple understanding:

```txt id="n7v3qm"
Star = Save

Fork = Copy
```

# Common Beginner Mistakes

## Starring Everything

Some beginners star hundreds of repositories without organizing them.

Only star repositories that are genuinely useful.

---

## Thinking Stars Give Contributions

Stars do not count as contributions.

GitHub contributions come from:

* commits
* pull requests
* issues
* repository activity

---

## Judging Projects Only by Stars

A repository with fewer stars may still be excellent.

Always focus on:

* quality
* documentation
* learning value
