# Repositories

A repository (often called a **repo**) is the most important concept in GitHub.

Every project on GitHub lives inside a repository.

In simple words:

> A repository is a folder that contains your project files, code, documentation, images, and project history.

When developers say:

```txt
"I created a GitHub repository."
```

they mean:

```txt
"I created a project space on GitHub."
```

---

# What is Stored in a Repository?

A repository can contain:

* source code
* images
* documentation
* configuration files
* project history
* issues
* pull requests

Example:

```txt
portfolio-website/
│
├── index.html
├── style.css
├── script.js
├── README.md
└── images/
```

Everything related to the project is stored inside the repository.

---

# Why Repositories Are Important

Repositories help developers:

* organize projects
* track project history
* collaborate with teams
* store documentation
* manage software development

Without repositories, managing projects becomes difficult.

---

# Real-World Example

Imagine you have different college subjects.

You would probably keep separate notebooks for:

```txt
Mathematics
Physics
Chemistry
Programming
```

Similarly, developers usually create separate repositories for different projects.

Example:

```txt
portfolio-website
weather-app
ecommerce-store
learning-platform
```

Each project gets its own repository.

# Public vs Private Repositories

GitHub allows two main types of repositories.

## Public Repository

Anyone can:

* view the repository
* read the code
* learn from it
* contribute (if allowed)

Example:
Many open-source projects are public.

---

## Private Repository

Only authorized people can access it.

Used for:

* personal projects
* company projects
* confidential work

---

# Creating a Repository

To create a repository:

### Step 1

Login to GitHub.

### Step 2

Click:

```txt
New Repository
```

### Step 3

Enter:

```txt
Repository Name
```

Example:

```txt
my-first-project
```

### Step 4

Choose:

```txt
Public
or
Private
```

### Step 5

Click:

```txt
Create Repository
```

Your repository is now ready.

---

# Repository Name Best Practices

Choose names that are:

✅ clear

✅ meaningful

✅ professional

Good examples:

```txt
portfolio-website
student-management-system
expense-tracker
learn-github
```

Avoid:

```txt
project123
testtest
newrepo
finalprojectfinal
```

---

## Issues

---

## Pull Requests

# Repository URL

Every repository has a unique URL.

Example:

```txt
https://github.com/username/project-name
```

Example:

```txt
https://github.com/johndoe/portfolio-website
```

This URL can be shared with anyone.

# Common Beginner Mistakes

## Creating Too Many Repositories

Some beginners create dozens of small, incomplete repositories.

Focus on:

* quality
* documentation
* consistency

instead of quantity.

---

## Ignoring README Files

A repository without a README often looks incomplete.

Always add proper documentation.

---

## Poor Repository Names

Use professional naming conventions.

Repository names create first impressions.

---
