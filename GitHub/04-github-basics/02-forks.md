# Forks

A **Fork** is one of the most important concepts in GitHub and open source.

In simple words:

> A fork is your personal copy of someone else's repository.

Forking allows you to:

* experiment safely
* make changes independently
* contribute to open-source projects
* learn from existing repositories

---

# Why Forks Exist

Imagine you find a project on GitHub that you want to improve.

You cannot directly change someone else's repository.

Instead, GitHub allows you to create your own copy.

This copy is called a:

```txt
Fork
```

---

# Real-World Example

Imagine your teacher shares a document with the entire class.

Instead of editing the teacher's original document, you create your own copy.

You can:

* make changes
* add content
* experiment freely

without affecting the original document.

A GitHub fork works in the same way.

---

# How Forking Works

```txt
Original Repository
          ↓
        Fork
          ↓
Your Personal Copy
```

After forking:

* the repository appears in your GitHub account
* you can modify it freely
* the original repository remains unchanged

---

# Example

Suppose you want to contribute to:

[freeCodeCamp Repository](https://github.com/freeCodeCamp/freeCodeCamp?utm_source=chatgpt.com)

Instead of editing the original repository directly:

### Step 1

Click:

```txt
Fork
```

### Step 2

```txt
Your Account/freeCodeCamp
```

Now you have your own copy.

# Why Open Source Uses Forks

Most open-source projects use the following workflow:

```txt
Original Repository
        ↓
      Fork
        ↓
Clone
        ↓
Make Changes
        ↓
Push Changes
        ↓
Pull Request
```

This workflow allows thousands of developers to contribute safely.

# What Happens After Forking?

After creating a fork:

You can:

* clone the repository
* edit code
* fix bugs
* improve documentation
* add features

without affecting the original project.

---

# Fork vs Clone

Many beginners confuse these terms.

| Fork                          | Clone                           |
| ----------------------------- | ------------------------------- |
| Creates a copy on GitHub      | Creates a copy on your computer |
| Happens online                | Happens locally                 |
| Used for contributions        | Used for development            |
| Stored in your GitHub account | Stored on your device           |

Simple understanding:

```txt
Fork = Copy on GitHub

Clone = Copy on Computer
```

# Common Beginner Mistakes

## Thinking Fork Changes the Original Repository

It does not.

Your fork is completely separate.

The original repository remains unchanged until your changes are accepted through a pull request.

---

## Confusing Fork with Clone

Remember:

```txt
Fork → GitHub Copy

Clone → Local Computer Copy
```

---

## Never Syncing Forks

Over time, the original repository may change.

Good contributors regularly update their forks to stay synchronized.

---

* improving README files

Forking makes this process safe and beginner-friendly.
